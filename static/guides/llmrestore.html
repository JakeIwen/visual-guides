llmrestore

Use
After a reboot (or after closing terminals by hand), reopen every Claude Code and Codex session that was open, each resumed in its own folder with its original options.
Command
llmrestore, an alias in ~/.zshrc on the Mac and ~/.bashrc/~/.zshrc on the Pi.
Source
~/dev/scripts/shared/sh/llm_restore.py (one file, standard library only). The Pi runs a copy at /home/pi/scripts/llm_restore.py.
Records
A cron job snapshots the open sessions every minute on both hosts.
Safety
Never opens a session that is already open, was launched in the last 2 minutes, or is kept running by LLM Switchboard. -n previews without opening anything.
Status

Usage

CommandDoes
llmrestoreReopen the recorded sessions that aren't open now.
llmrestore -nDry run: print what it would open and skip, and open nothing. Also --dry-run.
llmrestore -m 45Also reopen sessions closed up to 45 minutes before the last snapshot. Default 30, max 1440. Also --minutes.
llmrestore -H 2The same window in hours; decimals work (-H 1.5). Max 24. Use -m or -H, not both.
llmrestore --forceReopen even sessions launched in the last 2 minutes.
llmrestore --piOn the Mac: reopen the Pi's sessions as iTerm tabs over SSH. See Pi sessions from the Mac.
llmrestore --cronStatus: whether snapshots are on, the last snapshot, and how many sessions a restore would reopen.
llmrestore --cron off / onPause or resume the every-minute snapshot.
llmrestore --snapshotRecord the open sessions right now, without waiting for the cron minute.
llmrestore -hThe flag list.

Flags combine: llmrestore --pi -H 2 -n previews the Pi's sessions from the last two hours.

Run a dry run first after a reboot if you closed some sessions on purpose before shutting down; the window below decides whether they come back.

Reading the output

Each recorded session gets one line: skip with the reason, or open (would open in a dry run) with when it was last seen and the exact command that resumes it.

$ llmrestore -n
skip  claude api-3f: already open
skip  claude notes-61: kept running by llm-switchboard
skip  claude scratch-f2: transcript not found
would open  claude api-d3  (open at 2026-10-18 23:41)
      cd -- /Users/jacobr/dev/api && command claude --permission-mode bypassPermissions --resume 2b9c…
would open  codex Fix the import  (closed 4m before the last snapshot, last seen 2026-10-18 23:37)
      cd -- /Users/jacobr/dev/site && command /Users/jacobr/dev/scripts/shared/codex_autocontinue/run -- codex -s workspace-write resume 019a…
(3 closed more than 30 minutes before the last snapshot; widen with -m or -H)

Illustrative names and ids; the format is the tool's. A session is labelled by its title, or its id when it has none.

WordingMeans
open at …The session was still open in the last snapshot. After a reboot that is the usual case: the last snapshot before shutdown.
closed 4m before the last snapshotIt had already closed when that snapshot ran. Shutdown closes terminals one by one, so these are normal too.
(3 closed more than 30 minutes …)Older sessions are still recorded (for 24 hours) but outside the window. Rerun with -H 2 or similar to include them.
Opened as tabs of a new iTerm window.Mac result line after a real run.
Attach with: tmux attach -t llmrestorePi result line after a real run.
Nothing to reopen.Every recorded session in the window is open or skipped.

How far back

A snapshot keeps every session for 24 hours after it was last seen open, so the minute-by-minute record never empties when terminals close, whether that is the OS quitting them during a restart or you closing them by hand first. The restore then chooses what to reopen by when each session closed, measured from the last snapshot rather than from now:

23:05  you close the api session            (recorded, last seen 23:04)
23:30  you close the rest by hand           (recorded, last seen 23:29)
23:31  last snapshot before shutdown        ← the window is measured back from here
       … machine off overnight …
08:00  llmrestore                           → reopens the 23:29 sessions (2m before)
       llmrestore -H 1                      → also the api session     (27m before)
  • The list is the current boot's snapshot plus the previous boot's last one. Right after a reboot that is the previous boot's list; a session you have already reopened by hand shows as already open.
  • After a real restore (not a dry run), the previous boot's list is retired: sessions you close afterwards stay closed on the next run. Five boots of snapshots are kept on disk.
  • Sessions closed more than 24 hours before the last snapshot are gone from the record, which is why -H stops at 24.

What it never reopens

Skip reasonWhy
already openA live Claude or Codex process already shows that session. Checked at restore time, so running llmrestore twice opens nothing the second time.
launched under 120s ago (--force to reopen)A previous run started it moments ago and it hasn't registered yet. Stops a double run from opening everything twice.
kept running by llm-switchboardOn the Pi, LLM Switchboard restarts its own sessions; llmrestore leaves them to it and never lists the sessions it started.
transcript not foundThe session's transcript file is gone, so a resume would fail.

Only interactive terminal sessions are recorded: VS Code Claude sessions, claude -p, codex exec and the Codex app server are ignored.

Where sessions open

  • Mac: one new iTerm window, one tab per session. The original window and tab layout isn't reproduced.
  • Pi (run on the Pi): one tmux session named llmrestore, one window per session named after it. Attach with tmux attach -t llmrestore; a later run adds windows to the same session.
  • Each tab runs the session's resume command in a normal login shell, so when the session exits you are left at a prompt in its folder.

Pi sessions from the Mac

llmrestore --pi on the Mac asks the Pi which of its sessions to reopen, then opens each as an iTerm tab that SSHes to the Pi and resumes it there, like the SSH tabs they first ran in.

  • The Pi decides: it applies the window, the already-open check and the switchboard skip against its own processes, and prints its report in your Mac terminal.
  • Each tab runs ssh -t vanpi and, after the session exits, leaves a Pi shell open.
  • The SSH host is vanpi from ~/.ssh/config (LAN when reachable, else Tailscale). Set LLM_RESTORE_PI_HOST to use another.
  • Pi sessions opened this way count as open on the Pi, so a later --pi or a tmux restore on the Pi won't duplicate them.

The snapshot cron

A managed block in each host's user crontab runs a snapshot every minute. It is part of the tracked crontab files (macbook/crontab, pi/crontab_pi in the scripts repo), so reinstalling either one keeps it.

$ llmrestore --cron
Snapshot cron: ON (every minute)
Last snapshot: 2026-10-18 23:39, 8 session(s) open
Restore list: 13 session(s) open or closed within 30 minutes of the last snapshot (18 older, up to 24h) in /Users/jacobr/.local/state/llm-restore/restore
  • --cron off pauses snapshots with a flag file and leaves the crontab line alone; reinstalling a crontab can't flip it either way. --cron on clears the flag, takes a snapshot at once, and puts the crontab line back if it is missing or out of date.
  • --cron -m 45 or -H 2 makes the status count sessions within that window instead of 30 minutes.
  • A snapshot that finds a restore in progress skips that minute. Cron doesn't run while the Mac sleeps; the last snapshot before sleep stands.
  • Errors from the cron runs go to ~/.local/state/llm-restore/cron.log; the status line Errors were logged to … appears when it isn't empty.

The resume command

Every command starts with cd -- <folder> && command: the session reopens where it ran, and command bypasses shell functions such as a codex wrapper that adds its own flags, so the session's recorded options are used as they were.

What codexp and claudep add outside the flags comes back too: a Codex session restarts under the capacity-retry wrapper (shared/codex_autocontinue/run --) when it is installed, and on the Pi every command runs under env -u DISPLAY, so previews don't open on the Pi's desktop.

ToolKeptDropped
Claude CodePermission mode, model, effort, settings, agents, system prompts, plugin dirs, added dirs, allowed/disallowed tools, MCP config, --remote-control, --chrome, --dangerously-skip-permissions and similar session-wide flags. Ends with --resume <id>.The original --resume/--continue/--session-id, worktree and cloud modes, the initial prompt, and any option it doesn't recognise.
Codex-c, --enable/--disable, model, profile, sandbox, approval policy, added dirs, remote options, and unknown boolean flags. Ends with resume <id>.--cd, images, --last/--all, worktree, and the initial prompt.

The conversation itself comes back through the resume; the first prompt is never sent again.

Where it lives

  • Script: ~/dev/scripts/shared/sh/llm_restore.py, tests in macbook/tests/test_llm_restore.py. Python 3.9+ standard library; the Mac uses /usr/bin/python3.
  • State, private to the user, in ~/.local/state/llm-restore/:
    • restore: the generated shell script llmrestore runs. Its comments list each recorded session and its resume command, so it is readable on its own.
    • boots/: one snapshot per boot (the last five boots).
    • consumed.json: previous boots already restored. launched.json: the 2-minute launch guard.
    • cron-off: present while snapshots are paused. cron.log: cron errors. lock: keeps a snapshot and a restore from overlapping.
  • Sessions are found from ~/.claude/sessions/ and the running processes for Claude, and from the running Codex TUIs plus Codex's state database in ~/.codex/ for Codex.

Limits

  • Window and tab arrangement isn't reproduced; everything lands in one new iTerm window (or one tmux session on the Pi).
  • A Codex TUI that can't be matched to one thread is left out, with a warning: codex pid … line in --snapshot output and in the restore script's comments.
  • A session started and closed between two snapshot minutes is never recorded.
  • On the Mac, iTerm must be installed; macOS may ask once whether the terminal may control iTerm.
