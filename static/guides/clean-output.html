Claude /clean

Use
Read or copy your recent Claude Code exchanges, each prompt with its reply, without the Bash(...) calls, collapsed results and search summaries that surround them in the terminal. codexclean does the same for Codex sessions.

What it removes

Your own prompt is kept; the pane draws it on a tinted band above the reply. Claude Code stores every assistant message as content blocks. A reply's prose is text blocks; each tool call is a tool_use block, and its output comes back as a tool_result block in a user-role message. The terminal draws all three. /clean asks the engine for the session's messages, keeps the text blocks of the replies you name, and drops everything else.

Usage

Type the command at the Claude Code prompt. An exchange is one of your prompts, or a slash command that got a reply, together with everything the assistant wrote until your next one. Worker messages, background-task notices and scheduled wake-ups that arrive in between stay inside the exchange as one dim line, so a run with subagents reads as one block.

CommandEffect
/cleanOpen the pane with every exchange in the session, focused, scrolled to the newest reply.
/clean 1Only your last exchange.
/clean 3Your last 3 exchanges, oldest first. Any whole number; one larger than the session shows them all.
/clean turnsThe message each turn ended on, for every turn since your last prompt, each band naming what started the turn (your prompt, a worker message, a background task finishing, a scheduled wake-up). Finds a full report that later wrap-ups pushed off the screen.
/clean copyCopy instead of opening the pane, and print one confirmation line. The copy is plain text, as the pane shows it: each prompt marked ❯ the way the transcript marks your messages, the reply without markdown marks (no **, backticks or fences; links as text (url); tables aligned).
/clean mdCopy markdown instead, for copy and the pane's c: each prompt quoted (> ...) above its reply, --- between exchanges.
/clean toolsKeep each tool call as one quoted line, > Bash find ~/dev -type d -name node_modules..., in place.
/clean 3 tools copy mdWords combine in any order.

Keys while the pane has focus

KeyDoes
↑ ↓, PgUp PgDn, Home EndScroll the pane body: a row, a window, or to either end. The line under the pane follows.
cCopy everything the command chose, prompts included, as plain text (markdown when the command had md), through the terminal clipboard, or OSC 52 over SSH.
EscClose the pane and return the keyboard to the prompt. While Claude is working this closes the pane only; a second Esc stops the turn.
ctrl+x tabGive the pane the keyboard back after you started typing at the prompt, so Esc closes it again. What you typed stays in the prompt.
Tab, EnterWalk to the copy button and press it; same as c.
Mouse dragSelects text in the pane like any terminal text. Only what is on screen is selectable, so use c for a long reply.

The command runs at once even while Claude is working, instead of queueing behind the turn. Running it again while the pane is open replaces the content in place. Esc at an idle, empty prompt also closes the pane.

The pane

Inline above the prompt on a normal terminal, or docked beside the transcript in the fullscreen layout from 110 columns. Each exchange is your prompt on the theme's user-message background, the same tone the transcript puts behind your own messages, then the reply as markdown.

The pane opens on the newest reply, since that is usually what you came for. When worker messages or notices split the reply, it opens at the start of the last turn, the dim after … line on top; otherwise at the newest prompt. The line under the pane says which rows show and which way more lies. The pane's own first row scrolls away with the rest, so it can't carry that.

A pane left open keeps up with the session. When each turn ends it rebuilds from the same words you gave /clean and moves to the newest reply. After each prompt you send it takes the keyboard back, because while a turn runs Claude Code gives Esc at the prompt to interrupting the turn. The next key you type goes to the prompt as usual.

Add a filter

Each reply becomes a list of parts, { kind: 'text' | 'tool' | 'divider', text }, and FILTERS in hooks/clean.ts runs over that list in order. Each filter is a name and an apply(parts, opts) function; opts carries the command words (count, copy, tools, turns). Parts are text, tool or divider, the dim line that marks a worker message, notice or wake-up. Append an entry, save, and run /reload-plugins.

Built inDoes
drop-toolsRemoves tool parts unless tools was given.
strip-context-blocksRemoves <context>...</context> spans the reply hid from the terminal.
squeeze-blank-linesThree or more newlines become two; trims each part.
drop-emptyRemoves parts left empty by earlier filters.
collapse-dividersKeeps only the last of several dividers in a row, and drops one with nothing after it.

Example: drop the one-line narration that precedes a tool call, keeping only the paragraphs that make up the answer.

// hooks/clean.ts, appended to FILTERS
{
  name: 'drop-narration',
  apply: (parts, opts) =>
    opts.tools ? parts : parts.filter(p => p.kind !== 'text' || p.text.length > 160 || p.text.includes('\n')),
},

A filter that needs a new command word adds it in parseArgs and a field in CleanOptions, both in the same file. Check the change before reloading:

cd ~/dev/scripts/shared/claude-mods/clean-output
claude plugin validate .
claude plugin test .

Every file under hooks/ except register.tsx imports nothing from the engine, so the same views and filters can run over a Codex rollout file once a loader produces the same { role, text, toolUses, toolResults } shape.

Where it lives

  • Source folder: ~/dev/scripts/shared/claude-mods/clean-output/ in the JakeIwen/scripts checkout. .claude-plugin/plugin.json names it; hooks/hooks.json points at register.tsx; types/index.d.ts declares the three state values: what the pane shows, the origin of each submitted prompt, and the pane's scroll window.
  • Loaded from ~/.claude/settings.json: "env": { "CLAUDE_CODE_PLUGIN_DIRS": "~/dev/scripts/shared/claude-mods/clean-output" }. A second mod joins the value with :.
  • Modules: prompt-kinds.ts sorts transcript rows into your prompts, slash commands and injected messages; exchanges.ts and turn-endings.ts build the two views; clean-view.ts holds the pane sections, copy text, drawing budget, where the pane opens and the rows line.
  • Interactive sessions watch the folder: a save reloads the module when the folder goes quiet. /reload-plugins forces it.
  • Editor types: after the first load, .claude-plugin/types/ inside the mod folder holds the API declarations, and tsc -p . type-checks against them. The engine writes that folder and gitignores it.
  • Built with the plugin-authoring skill in Claude Code 2.1.300. The plugin API is early access and may change between releases; a break shows as a dim line in the transcript naming the mod and the reason.

Codex: codexclean

The same view for a Codex session, as a shell command on the Mac and the Pi. It reads the session file in ~/.codex/sessions/ and runs it through the mod's own grouping, filters and plain-text rendering. Codex logs each typed prompt and what started each turn, so nothing is guessed: a goal continuation or a compaction is one divider line, and your !commands are left out.

codexclean [N] [turns] [tools] [md] [copy | open | watch | print] [--session <id|file>]
CommandEffect
codexcleanIn a normal terminal: print every exchange, each prompt on a shaded band, paged with less (opening at the end) when longer than a screen.
!codexclean (inside Codex)Save the view as a page in ~/.agent/artifacts/, open it on the Mac, and print one line. On the Pi the line gives the page's path under the Mac's mount.
codexclean 1, turns, tools, mdAs for /clean.
codexclean copyCopy the plain text (md for markdown) and print one line. On the Pi the copy goes through the OSC 52 pbcopy shim.
codexclean openThe page, from anywhere. One page per session, rewritten each time.
codexclean watch --session <id>In a split pane: redraw the newest exchange (or the last N) as Codex writes it. Ctrl+C stops. !codexclean watch prints this command with the session's id filled in.
!codexclean printPrint inside Codex anyway.

The session is the --session id (any part of it) or file, else the one it runs in ($CODEX_THREAD_ID, which Codex sets for !commands), else the newest session started in the current folder.

Why a bare !codexclean doesn't print: Codex records a !command's output as a user message, so it joins the model's context on the next turn. Printing a session there would feed the model its own history again.

Installed

  • codex/build.mjs in the mod folder strips the TypeScript types from the engine-free modules (Node 22.13 or later) and lays them out with codex/codexclean.mjs as plain ES modules, which run on the Pi's Node 20.
  • zsh codex/deploy.zsh builds and installs on the Pi, then the Mac: ~/.local/share/codexclean/ plus a launcher at ~/.local/bin/codexclean, on PATH for Codex's !commands on both machines.
  • The installed copies don't follow the checkout. Re-run the deploy after editing any of the shared modules.
  • Files from before Codex logged items (about 2026-09) are read from their message events; a 266 MB one takes about 3 s.

Limits

  • Within one assistant message all text comes before its tool lines, because the engine hands the text blocks joined. Across messages the order is right, and with tools off it makes no difference.
  • An exchange starts at each of your prompts and at each slash command that got a reply, so a command you ran mid-reply starts a new one. Use /clean 2 if the last exchange looks short.
  • The mod records where each prompt came from as it is submitted. Rows from before it loaded are sorted by text markers; a scheduled wake-up from that time has no marker and counts as one of your prompts, splitting the exchange.
  • One drawing holds 100,000 characters of markdown. The pane keeps about 90,000 and leaves out the oldest exchanges past that; the header row says how many, and copy still copies all of them.
  • The rows line lives in the band above the prompt, which surveys also use; while one is up the line steps aside. It shows only when the content is taller than the pane.
  • An inline pane takes about a third of the screen unless you drag or key it taller; the size you set is kept for the session. The dock is used only in the fullscreen layout.
  • Copy goes through Claude Code's clipboard path. Over plain SSH without OSC 52 support the command reports no-clipboard.
  • The plain copy reads markdown line by line: fences, headings, lists, tables, quotes and inline marks. Nested lists keep their indent; HTML in a reply is copied as written.
  • Codex has no plugin surface that draws in its terminal, so its version is a shell command rather than a pane (Codex).

Troubleshooting

SymptomFix
/clean is unknownThe session started before the env entry existed, or the folder moved. Check grep PLUGIN_DIRS ~/.claude/settings.json, then start a new session.
clean: no reply found yet.No assistant reply since the session began (or, for turns, since your last prompt).
clean: pane not placed (...)The surface cannot draw panes (headless, -p). Use /clean copy.
clean: copy failed (no-clipboard)The terminal refused the clipboard write. In iTerm2, allow clipboard access in Preferences › General › Selection.
A dim line names clean-output and a refused hookThe API changed under a Claude Code update. Run claude plugin validate . in the mod folder; the message names the call.
One exchange shows up as twoA wake-up or message from before the mod loaded was counted as your prompt. Prompts submitted after it loaded are sorted exactly; use /clean 2 for that session.
Esc stopped the turn and the pane stayedYou had typed at the prompt since the pane last held the keyboard, so Esc belonged to the turn. Press ctrl+x tab, then Esc. Sending a prompt hands the keys back to the pane on its own.
The pane opens at the top or the very bottom, not at the newest replyThe pane draws a moment after it opens, and the mod retries for under a second before falling back to the end. Press Home, End or PgUp to move; the rows line shows where you are.
codexclean: no Codex session started in …No session file names this folder as its start. Pass --session <id> (the id is in Codex's footer), or run it from the session's folder.
