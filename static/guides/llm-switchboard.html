The page and its rows

The header counts kept sessions and those with Remote Control connected, and reports whether the Mac is online. New starts a Pi session; the gear opens Settings. The search box and filter row stay at the top while you scroll.

  • Title: tap the row body to expand or collapse it. A title can occupy two lines. The paired tag identifies Pi · Claude, Pi · Codex, Mac · Claude or Mac · Codex.
  • Folder and age: the folder is teal on the Pi, violet on the Mac; the age is time since last activity. Tap the folder to filter to it alone; tap it again when it is the only selected place to remove that filter. Transcript size appears on collapsed rows when sorting by Largest first, and in expanded rows.
  • State pills: show the supervisor state, Working, Open in a terminal, or memory in MB RAM. Ordinary collapsed rows show at most two; a Mac action adds its own status pill. Queued means enabled but not yet reconciled; New means no transcript has been written yet.
  • Switch at the right: only Pi Claude rows can be kept running. An orange edge marks kept rows. The checkbox at the left selects; it does not expand. Blue marks selection or the keyboard cursor, not keep-running.
  • Expanded row: actions come first, then loaded messages or screen, state/exit information, shell commands on computers, the id and transcript size. Delete is here, not on the collapsed row.

The page refreshes every 4 seconds by default, pauses while its tab is hidden, and refreshes on return. If the service stops answering, it keeps the last list and says so. Ordinary refreshes preserve open rows and forms.

Keep a session running

Turn on a Pi Claude row's switch. The supervisor opens it in the dedicated tmux -L llm-switchboard server, through claudepd, with Remote Control. That function supplies the same settings as an interactive launch: bypass permissions and no Model Gateway, which permits Remote Control. The manual resume command in Settings does not change it.

  • The session appears in the Claude app and at claude.ai/code under its Remote Control name. Blank means the session title. Open in Claude uses the link from its last connection.
  • After an exit, relaunch waits double from 10 seconds up to 10 minutes. A run lasting five minutes resets that backoff. A session open in another Claude process waits for it to close; an unreachable API makes it wait for the network.
  • The tmux windows survive service restarts and are adopted again. Enabled sessions start again after boot. Each process uses roughly 300 MB, so keep a handful, not dozens.
  • Restart relaunches a kept session now. Switching it off closes its window without deleting the transcript; stopping or restarting during a turn asks for confirmation.

Find sessions

Type in Search sessions to filter as you type. Every term must match, ignoring case, against title, first prompt, folder, id or Remote Control name. This is a substring search, not a search through the full conversation. Show and Places narrow it further. The info icon, Search syntax, explains both search modes and desktop keys.

Show

The first filter button shows its current value, initially All sessions. Open it for the Show menu: All sessions, Kept running or Open now; and All tools, Claude or Codex when Codex is available in the list. Open now means enabled or detected open elsewhere, not necessarily an active turn.

Headless runs includes runs nobody typed in: claude -p, codex exec, and Codex threads opened by other apps through its API. They are hidden by default; a kept one is not hidden by that rule. The option appears when there are headless runs, or it is already checked.

Places and sort

All places opens Places: folder chips grouped by machine, with Find a place above them. Each machine heading is also a selectable chip: pick it to include every folder on that machine, even folders omitted from the normal menu. Pick several places to show their sessions together. A Pi folder and a Mac folder with the same path are separate places.

  • Folder labels omit the shared ~/ prefix. Counts follow the current query, Show choices and headless setting, before Places is applied. Places with no matching sessions disappear unless already selected.
  • The normal folder choices come from Settings: by default home and up to two levels below it, at least two sessions per machine, no hidden prefixes. Eligibility uses the unfiltered list; displayed counts use the current filters. A selected exception remains removable and says outside default folders.
  • Clear removes every selected place. Invert reverses the visible folder chips, respecting Find a place; it does not invert the machine-heading chips. Done closes the picker. On a phone this is a bottom sheet; on desktop a popover. The find field and footer stay put while chips scroll.
  • The toolbar button names one selected place or the number of places. There are no separate selected-folder chips below the toolbar. Tool, headless, Places and Sort choices are remembered in this browser.

The Sort button shows its chosen order, shortened on a phone to Kept, Recent, Oldest, A–Z, Folder or Size. Reset stays at the end of the filter row: it resets status, tool, Places and headless visibility. It does not clear the search text or change Sort; use the search box's clear control and the Sort menu for those. Reset is dimmed when those filters are already at their defaults.

Search inside transcripts

With words in the box, choose Search inside transcripts for “…” below the filters, or press Enter in the box. The placeholder becomes Search inside transcripts. Editing now waits for Enter rather than filtering live. The filter row gives way to a scope line: Sessions to go back, Transcripts, the matched-session count and index status. Session-list filters and Sort do not limit transcript results.

The bridge converts is:claude/is:codex to tool:claude/tool:codex and omits session-only is:, state:, title: and id: terms, listing them under Ignored inside transcripts:. Choose Sessions, press Esc, or clear the transcript box to return to the earlier Sessions query and filters.

  • Pi results search your prompts and visible replies in both tools, newest match first. Each appears as an ordinary row with its match count, latest-match age and excerpt. Expand for normal actions or use its keep-running switch directly.
  • Open matches shows up to twelve matching records, each with the message before and after, labelled You or Reply. Hide context closes them.
  • Open the page over HTTPS (https:// plus the Pi's Tailscale name) in a browser on the Mac, and the page also asks the Mac's own search endpoint, dev.llm-switchboard.host-search on 127.0.0.1:8778. Mac sessions then show excerpts and Open matches like Pi ones. The text goes from the Mac straight to that browser; it never passes through the Pi. Chrome asks once to allow Apps on device; allow it.
  • Anywhere else (the phone, plain http://, or when the Mac endpoint doesn't answer within 3 seconds), Mac results say Title or folder match only; the Mac keeps its transcripts and have no excerpts. When the Mac was asked and didn't answer, the scope line adds Mac: titles only. In a shell on the Mac, llmsearch or llm-switchboard search searches the same index.
  • The scope line reports index freshness; its tooltip has the full index status, including session count. Missing, updating and error states appear there too.

word another · "two words"All words in one prompt or reply, or a phrase. Whole words, case and accents ignored: pcan finds PCAN-USB and pcan_view, not PCANView.

The Pi updates its index every 30 seconds at low priority, reading additions. The first build can take a minute or two. The Mac keeps its own index of its own transcripts, updated every 30 seconds by the background launchd job dev.llm-switchboard.search-index; the index and its results never leave the Mac. Thinking, tool calls, tool output, injected instructions and Codex subagents are not indexed. Searches exceeding five seconds stop: add a rarer word or phrase. In a shell on either machine, llmsearch uses that machine's index; llmsearch --grep searches raw transcripts instead, slowly, including material the index leaves out.

Tap a row body, or use Enter on the keyboard cursor. Actions vary by machine and tool. Rename, Move, Fork and RC Name open small forms rather than permanent fields.

Names are unique per folder across Claude and Codex, ignoring case and spacing; new, rename, move and fork cannot create a duplicate.

Selection and keyboard

In the Sessions list, use the left checkbox, ⌘/Ctrl-click to toggle a row, or Shift-click for a range. Plain row-body clicks expand instead. Filtering removes hidden rows from the selection.

The bottom bar shows the count and Keep running, Delete, a More selection actions menu (three dots), and a close icon to Clear selection. On desktop Stop keeping and Move… are also visible; on a phone they are in the menu as Stop keeping and Move to folder…. The menu always offers Select all shown.

  • Keep/stop applies only to Pi Claude sessions, skipping Codex and Mac rows. Keeping more than two asks for confirmation; stopping busy sessions confirms too.
  • Move uses one destination for the selected Claude rows, including queued Mac moves; Codex is skipped. Open, offline or list-only rows are left alone. Name conflicts and other failures are reported per session.
  • Delete confirms and reports progress. A wholly local batch offers one Undo; a batch with Mac rows reports queued actions instead.

New session

Choose New in the header, then Tool (if Codex is enabled and available), Folder and Name. Codex also requires First message. Choose Create. These are Pi sessions, even when you were viewing Mac rows.

  • Folders must already exist and have sessions. Claude also requires a folder Claude Code already trusts in ~/.claude.json; home itself is not allowed because it would wait at a trust prompt. Codex can use an existing home folder. The form explains unavailable folders.
  • Claude starts through claudepd --session-id … --name … with Remote Control and keep-running on. New lasts until it writes a transcript; then watch Starting and Remote Control on. A ready toast offers Open in Claude; a problem toast offers Details. If notifications are configured, one also announces readiness or attention.
  • Codex starts on First message immediately with approval policy never; nobody needs to approve the turn. It saves a session only after receiving a message. Watch Working; no readiness notification is sent.

Delete and restore

Choose Delete in an expanded row or the bulk bar, or use the desktop delete shortcut. Confirm first. A local delete offers Undo in a toast for ten seconds. Later, open Recently deleted (…) · kept 30 days at the end of the Sessions list and choose Restore.

  • Pi Claude: deletion stops a kept session and moves its transcript and companion folder to trash. Undo or Restore brings it back with keep-running off. A new session with no transcript is simply stopped and forgotten; there is nothing to restore. A session open in another Claude process cannot be deleted here.
  • Pi Codex: deletion archives it in Codex, hiding it from the app and TUI too; Restore unarchives it. Wait for an active turn to finish before deleting. Permanent deletion can be refused while a fork's history refers to it; it stays archived.
  • Mac: deletion and restoration are queued, not immediate and not undone with the local Undo toast. Wait for the next push, then use Recently deleted / Restore. The Mac keeps its own trash.

Empty Pi trash now permanently clears only the Pi's trash after a Delete forever confirmation. Otherwise trash expires after 30 days. Mac trash expires on the Mac; the Pi's empty button does not clear it.

Codex sessions

Pi Codex rows come from the shared app-server daemon, never by editing Codex's files or database directly. Its API is experimental; a daemon failure must leave Claude sessions working. The last good Codex list is retained during a restart.

  • No keep-running switch, per-session Remote Control name, Terminal screen or Restart. The daemon holds sessions; Codex remote control is a machine-wide setting. Turns can continue after their client disconnects.
  • Rename…, Recent messages, Fork… and Delete are available on Pi Codex rows. Rename is visible in Codex too. There is no Move: Fork to another folder instead.
  • New needs a First message. Delete/Restore means archive/unarchive. A working turn blocks deletion.
  • Do not treat the absence of Open in a terminal as proof that no Codex TUI is open: terminal detection is not the same as Claude's process detection, and some TUI configurations bypass the shared daemon.
  • Resume uses the configured Codex command followed by resume <id>. Short ids use the last eight characters for Codex and first eight for Claude. The same per-folder name rule covers both tools.

Mac sessions

The Mac pushes metadata over SSH every 10 seconds while awake. The Pi does not connect into it. The header shows online status; after 35 seconds without a push it says offline with last-seen time, rows dim, and actions lock until the next push.

  • Rows carry ids, titles, folders, times, sizes and open/busy state. Unnamed Mac sessions use a one-line prompt title: Claude and Codex take the first prompt, up to 120 characters (Codex through the daemon's preview, or from its files when the Codex app isn't running). Only a Codex session with no prompt yet says (untitled). A Claude transcript with no prompt is not listed. Other prompt text, replies and screens stay on the Mac.
  • No keep-running, Restart, Recent messages or Terminal screen. Resume commands are for a shell on the Mac, using the install's configured commands; copying one does not start it remotely.
  • Rename…, Move… (Claude only), Delete and Restore queue work for the Mac to check and run on its next push. A Claude row's Move arrow offers Fork on the Mac… and Fork onto the Pi…. Mac Codex has a direct Fork on the Mac….
  • One action per session at a time. Open or working sessions cannot be changed; offline sessions wait; Mac Codex is list-only without its app-server daemon. A fork on the Mac never starts or keeps the copy running. Queued actions cannot start processes or send prompts.
  • Fork onto the Pi… is Claude-only and the one explicit transcript upload. It maps the same home-relative folder onto the Pi, which must already exist, and creates a new not-running session with a free name. The Mac must post a notification and log the upload; limit 16 MiB and ten uploads per hour.

Setting up the Mac

Clone the repo, configure this install's private machine identifiers and SSH destination in untracked local.env using local.env.example, then run bash ~/dev/llm-switchboard/scripts/setup-mac.sh. It uses Homebrew Python 3.11+, creates a dedicated SSH key, authorizes it through the normal Pi SSH login, creates the checkout's .venv, links llm-switchboard into ~/.local/bin, pushes once, builds the Mac's search index and loads dev.llm-switchboard.host-agent, dev.llm-switchboard.search-index and dev.llm-switchboard.host-search. For the page's Mac transcript search, set LLM_SWITCHBOARD_PAGE_ORIGINS in local.env to the page's HTTPS address (no trailing slash) before running it; only those origins may read the Mac's answers.

The key is restricted to host-exchange: no shell, terminal or forwarding. The Mac opens no listening port. Its logs are in ~/Library/Logs/llm-switchboard/. To unload both jobs from the checkout, use /opt/homebrew/bin/python3 -m llm_switchboard host-install --unload; after a Homebrew Python version upgrade, run host-install again.

From a shell

Run the CLI on the Pi. On the Mac, search and index work the same against the Mac's own transcripts. Ids accept unique prefixes; Codex also accepts the short id shown by list. Brackets below denote optional arguments, not literal shell text. Resume commands can use a shell function configured in Settings.

llm-switchboard list
llm-switchboard status
llm-switchboard enable <id> [--name "phone name"]
llm-switchboard disable <id>
llm-switchboard restart <id>
llm-switchboard attach <id>       # detach: Ctrl-b d
llm-switchboard new --list
llm-switchboard new ~/dev/example "try a fix"
llm-switchboard new ~/dev/example "add tests" --codex "test the parser"
llm-switchboard fork <id> "another approach" [--folder ~/dev/example] [--keep]
llm-switchboard search 'retry by:me'
llm-switchboard search 'retry' --session claude:<id>
llm-switchboard search 'retry' --json
llm-switchboard search --json --before 2 --after 3 -- 'retry'
llm-switchboard index [--quiet]   # --quiet: print only if something changed
llm-switchboard settings
llm-switchboard settings set folders.depth 3
llm-switchboard settings set folders.hidden "~/private,~/archive"
llm-switchboard settings set claude_command claude
llm-switchboard stop-all          # kills the dedicated tmux server
journalctl --user -u llm-switchboard -f

search -B N / --before N and -A N / --after N show that many lines before and after each matching line in the latest matching prompt or reply, not neighboring messages. Counts are non-negative; an omitted side is zero. Overlapping or adjacent windows merge, with a -- line between separate groups. Long lines show a 300-character window with … on cut sides, keeping a matching term visible. If no line contains the query text (for example, an accent-insensitive index match), the ordinary excerpt is used. Either flag adds a context string to each JSON result; plain output prints those lines instead of the excerpt. Without the flags, output is unchanged. --session ignores them.

search --json emits one JSON record per result for scripts; exit 3 means the index is not built yet. host-authorize <host-id> < key.pub installs a Mac's restricted key on the Pi; the setup script runs it over SSH. The CLI's host commands are not a way to launch sessions on the Mac.

Where it lives

  • The Pi user unit llm-switchboard runs bin/llm-switchboard serve from ~/dev/llm-switchboard. It listens on localhost and Tailscale by default, not the LAN. serve --host ADDR changes binding and can be repeated; tailscale selects the Tailscale interface. User lingering permits boot startup.
  • The checkout's wrapper uses .venv/bin/python. The backend needs its locked HTTP dependencies; do not restart it without that environment. The React page is built from web/ into web/dist. After a deployed code change, systemctl --user restart llm-switchboard adopts existing tmux windows rather than stopping sessions.
  • ~/.config/llm-switchboard/ holds sessions.json, settings.json and codex-trash.json. ~/.local/share/llm-switchboard/ holds trash/, per-host snapshots and queues in hosts/, and transcript-search.sqlite3 with its -wal, -shm and .lock companions. To rebuild from scratch, stop the service, remove those four index files, then start it again.
  • Claude transcripts stay in ~/.claude/projects/*/*.jsonl. Codex is accessed through its daemon socket under ~/.codex/app-server-control/, not by editing its storage.
  • On the Mac, the launchd plists are ~/Library/LaunchAgents/dev.llm-switchboard.host-agent.plist, dev.llm-switchboard.search-index.plist and dev.llm-switchboard.host-search.plist; logs, including uploads and index updates, are in ~/Library/Logs/llm-switchboard/. The Mac's search index is ~/.local/share/llm-switchboard/transcript-search.sqlite3; to rebuild it, launchctl bootout gui/$(id -u)/dev.llm-switchboard.search-index, remove the four index files, then run host-install. Its action ledger and upload quota are in ~/.config/llm-switchboard/, and its trash in ~/.local/share/llm-switchboard/trash/.
  • The app's whole suite is .venv/bin/python -m unittest discover -s tests -f, including backend, Node and rebuilt-page checks. Browser checks use isolated fixtures through browser_clean, not real sessions. The app repo requires this guide to follow behavior changes.
