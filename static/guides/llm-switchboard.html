LLM Switchboard

Use
Keep chosen Claude Code sessions running on vanpi with Remote Control on, so the phone can always reach them, and manage every Claude Code and Codex session on the Pi in one place: search (inside transcripts too), rename, fork, move, delete with undo, start new ones. The Mac's sessions show too while it is awake, pushed from the Mac.
Open
vanpi:8777 over Tailscale only (the Pi's MagicDNS name or tailscale ip -4 address), or 127.0.0.1:8777 on the Pi itself. Not from the van LAN. No login; anyone on the tailnet can use it.
Kind
A user systemd service on the Pi (llm-switchboard): a supervisor that runs sessions in tmux, plus this web page and a CLI. Python standard library, no build step.
Source
~/dev/llm-switchboard on the Pi · JakeIwen/llm-switchboard (private). The service runs from that checkout.
Status
In daily use Codex support added 2026-10-15 on an API Codex marks experimental. Mac sessions added 2026-10-18; transcript search 2026-10-19.

Keep a session running

Flip the switch on a Claude session. The supervisor opens a window in its own tmux server (tmux -L llm-switchboard) and runs claudepd --resume <id> --remote-control <name> there, from the session's working folder, so it has the same settings as an interactive claudepd: bypass permissions and no Model Gateway, which is what lets Remote Control work. From then on:

  • The session appears in the Claude app and at claude.ai/code under its Remote Control name (blank means the session title; change it in the panel, applied at the next launch). Open in Claude ↗ in the panel is the link from its last connection.
  • If claude exits, it is relaunched: after a quick failure the wait doubles from 10 s up to 10 minutes; a run of five minutes or more resets that.
  • It is not launched while the same session is open in another claude process (an SSH terminal, say). It waits for that process to exit, then starts.
  • It waits for api.anthropic.com to be reachable before launching, which matters when the van's uplink is down.
  • The tmux server survives a restart of the service, and every enabled session starts again at boot. The list of enabled sessions is ~/.config/llm-switchboard/sessions.json.
  • Each running session is a full claude process, roughly 280 MB on the Pi 4, so keep a handful, not dozens.

Find sessions

Type in the search box. Every term must match, case ignored, against the title, first prompt, folder, id and Remote Control name. The folder menu and both filter rows combine with the search, and the menu's counts follow it.

TermMatches
word · "two words"A word anywhere, or an exact phrase.
-word · -dir:tmp · -"a phrase"Excludes; works in front of any term below.
dir:obd (also folder:, in:)Part of the folder path.
title:telem · id:c969Only the title, or only the id.
is:kept · is:offKeep-running switch on, or off.
is:running · is:attention · is:elsewhereKept sessions in that supervisor state. state:backoff matches any exact state name.
is:open · is:busyOpen in any claude process; working on a turn right now (Claude or Codex).
is:claude · is:codexOne tool, the same as the switch.
age:<2d · age:>1wLast activity newer or older than that; units m, h, d, w.

An unparseable term shows a message under the toolbar instead of matching nothing. / jumps to the search box from anywhere on the page.

Search inside transcripts

Transcripts, next to the search box, switches it to searching your prompts and the replies in the Pi's Claude Code and Codex sessions, both tools in one list, newest match first. Type a query and press Enter; Esc, the button again, or clearing the box goes back to the session list as it was. The filters, sort and folder menu are hidden meanwhile.

  • Each result shows the session, how many records match, when the latest one was, and its text around the match.
  • Open matches lists up to a dozen matches with the message before and after each, labelled You or Reply, and a copyable claudepd --resume or codexp resume line.
  • Mac sessions appear only when the words are in their title or folder ("title/folder match only"), with their resume command: their text never leaves the Mac.
  • The line under the toolbar says how many sessions the index holds and when it last caught up.
TermMatches
word another · "two words"All the words in one prompt or reply, or an exact phrase. Whole words, case and accents ignored: pcan finds pcan_view and PCAN-USB, not PCANView.
-word · -"a phrase"Leaves out sessions where it appears anywhere.
tool:claude · tool:codexOne tool only.
dir:obdPart of the session's folder.
by:me · by:replyOnly your prompts; only the replies.
age:<2d · after:2026-10-01 · before:2026-10-18By the session's last activity.

The index lives on the Pi and updates itself every 30 seconds at low priority, reading only what was added. Its first build reads every transcript and takes a minute or two; searches find nothing until it finishes. A query that would take over 5 seconds is stopped: add a rarer word or a phrase. Thinking, tool calls, tool output, injected instructions and Codex subagents are not indexed. In a shell, llmsearch searches this index; llmsearch --grep greps the transcripts instead, slowly, thinking, tool calls and tool output included (and for Codex, injected instructions and subagents).

Sort

The drop-down at the end of the toolbar orders whatever the search and filters leave. Ties keep the previous order, so "Folder, then recent" lists each folder's sessions newest first.

OrderUse it for
Kept firstThe default: sessions with the switch on, then everything else by last activity.
Recent activity · Oldest activityWhat you were just doing; or, with Select all, clearing out sessions nobody has touched in months.
Name A–ZFinding a session you know by name, and spotting near-duplicate names before a rename is refused. Case is ignored and numbers sort naturally (2 before 10).
Folder, then recentReviewing one project's sessions in context when more than one folder is shown.
Largest firstFinding the long conversations worth forking or trimming. Sessions without a known size go last.

The details panel

▾ (or Enter on the highlighted row) opens it under the row. What it offers for a Claude session:

ControlDoes
Open in Claude ↗The claude.ai/code link from the session's last Remote Control connection. Only after it has connected once.
Recent messagesThe last few prompts and replies, read from the transcript, to tell similar sessions apart.
Terminal screenKept sessions: the tmux window's last 200 lines, or the screen as it was when claude last exited. The place to read a waiting prompt. × in its corner closes it.
RestartKept sessions: relaunch now.
Title · RenameA kept session that is idle gets /rename typed into its window; a closed session gets Claude Code's own title record appended to its transcript. Either way the new title shows everywhere Claude Code lists sessions.
Working folder · MoveMoves the transcript under the other folder's project directory and rewrites its cwd fields, so claudepd --resume works from there. A kept session restarts in the new folder. Type a path or pick one from the list of known folders.
Move ▾ · Fork…The arrow beside Move opens a menu with Fork…: copy the conversation so far into a new session with a new id and a name you choose, in this folder or another, optionally kept running. The original is only read, so it can be running. The copy drops the original's Remote Control link and any half-written last line.
Remote Control name · SaveThe name shown in the Claude app. Blank uses the title. Takes effect at the next launch.
Resume in a shell on the PiA copyable cd … && claudepd --resume … line. Kept sessions also get llm-switchboard attach <id>, which opens the tmux window in your terminal (detach with Ctrl-b d).

Rename, Move and × are refused while the session is open in another claude process, the same rule as clauderm and claudeclean: a running process owns its transcript. No two sessions in one folder may share a name (case and spacing ignored); rename, fork, move and new are refused with a message when they would make a duplicate.

New session

+ New session asks for a tool, a folder and a name; Codex also needs a first message.

  • Folder: only folders that already have sessions and still exist are offered. For Claude the folder must also be one Claude Code already trusts (per ~/.claude.json), and ~ is never offered, because Claude Code asks about it every time and the session would sit at that prompt. Codex has no trust prompt, so any existing folder works, ~ included.
  • Claude: the session starts in tmux through claudepd --session-id … --name … --remote-control … and is kept running like any other. The card says New until the transcript exists, then Starting, then Remote Control on with an Open in Claude button. A push notification goes out through ~/scripts/ntfy_send.sh with the claude.ai link, or a "needs attention" one if it does not come up.
  • Codex: the session starts in the Codex daemon and begins working on the first message at once, with approval policy never (what codexp passes), so nobody has to be there to approve anything. Codex saves a session only once it has a message, which is why the field is required. The card shows Working until the turn ends; there is no notification.
llm-switchboard new --list                                   # folders a new session may use
llm-switchboard new ~/dev/obd-things "ignition-off logger"
llm-switchboard new ~/dev/can-fd "decoder cleanup" --codex "tidy the DBC loader and add tests"

Delete and restore

× on a row, ⌫, or the bar's Delete. A toast offers Undo for a moment; after that the session sits under Recently deleted with a Restore button for 30 days, then goes for good. Empty now does that immediately, after a confirmation.

  • Claude: a kept session is stopped first. The transcript and its companion folder move to ~/.local/share/llm-switchboard/trash/; Restore moves them back. Refused while the session is open in another claude process.
  • Codex: the session is archived in Codex (its own soft delete), so the Codex app and TUI stop listing it too; Restore unarchives it. After 30 days or Empty now it is deleted from Codex. Codex refuses to delete a session that a fork's history still points at; that one simply stays archived. A session working on a turn cannot be deleted until it finishes.

Codex sessions

Codex sessions are read and changed through Codex's shared app-server daemon, the same socket the Codex TUI uses, never by editing the files under ~/.codex (Codex keeps their state in a database as well). The daemon normally runs all the time on the Pi; the page lists sessions from its state database, which answers in milliseconds, and keeps the last good list if the daemon restarts (it does after a Codex update).

Mac sessions

The Mac's Claude Code and Codex sessions appear in the same list, tagged Mac, while the Mac is awake. The Mac does the work: a launchd job there runs the same package, computes its own rows every 10 seconds and pushes them to the Pi over SSH with a key of its own, which the Pi accepts for one command only. The Mac opens no port and runs no web page, and the Pi has no way into the Mac.

  • Online or not is judged only from the last push. After 35 seconds without one, the header says m4mac: offline, last seen HH:MM, the Mac's rows grey out, and their actions are disabled until it pushes again. Nothing pings the Mac.
  • What crosses: ids, titles, folder, times, size and whether the session is open or busy. Prompts, replies and terminal screens stay on the Mac, so a Mac row has no Recent messages, Terminal screen, keep-running switch or Restart, the search box matches it by title and folder only, and a session with no title shows as (untitled) rather than its first prompt.
  • Actions are queued, and the Mac runs them on its next push after checking them itself: Rename, Move, Fork on the Mac… (never started or kept running), Delete to the Mac's own trash, and Restore from Recently deleted. Nothing that starts a process or sends a prompt can be queued. The Mac refuses a session that is open in a claude process there, or a Codex session working on a turn.
  • Fork onto the Pi… (Claude sessions only) is the one way a conversation leaves the Mac. The Mac posts a notification, logs the upload and sends that one transcript (at most 16 MiB, 10 uploads an hour). It becomes a new Pi session, not running, in the Pi folder with the same path under the home folder (~/dev/obd-things on the Mac goes to ~/dev/obd-things on the Pi), which must already exist there. Its name must be free in that folder.
  • Mac Codex sessions need the Codex daemon running on the Mac for any action; without it they are listed from disk, read-only. They have no Move and no Fork onto the Pi.
  • The resume command uses plain claude --resume or codex resume, to paste into a shell on the Mac.

Action status

A box above the list shows the last ten minutes of Mac actions, each with its state:

StateMeaning
queuedWaiting for the Mac's next push.
queued (delivered; awaiting result)The Mac has it; its result comes back within seconds.
doneThe Mac did it. A fork names the new session's id.
failedThe Mac (or, for Fork onto the Pi, the Pi) refused it; the reason follows.
expired60 seconds passed. "Nothing ran on the Mac" if it was never delivered; "outcome unknown" if the Mac got it but no answer came back, so check before retrying. An action is never sent twice.

One action per Mac session at a time. Keep running and Stop keeping in the bar skip Mac rows; Move and Delete there queue them. Empty Pi trash now leaves the Mac's trash alone; it empties itself after 30 days.

Setting up the Mac

On the Mac, with Homebrew's Python 3.11 or newer, clone the repo and run its setup script. It creates the key ~/.ssh/llm-switchboard-m4mac, installs it on the Pi with host-authorize over the Mac's normal SSH login to vanpi, pushes once, and loads the launchd job dev.llm-switchboard.host-agent.

git clone https://github.com/JakeIwen/llm-switchboard.git ~/dev/llm-switchboard
bash ~/dev/llm-switchboard/scripts/setup-mac.sh
cd ~/dev/llm-switchboard && /opt/homebrew/bin/python3 -m llm_switchboard host-install --unload   # stop it
tail -f ~/Library/Logs/llm-switchboard/agent-error.log

The key's line in the Pi's ~/.ssh/authorized_keys is restrict,command="…/bin/llm-switchboard host-exchange m4mac" …: no shell, no terminal, no forwarding. Each push is one ssh run carrying JSON both ways, over a shared connection so it stays cheap. After Homebrew upgrades Python to a new version, run host-install again.

From a shell

Everything the page does, from any shell on the Pi. Ids can be any unique prefix; Codex sessions also go by the short id list shows.

llm-switchboard list                 # every session, enabled first; "codex" in the state column
llm-switchboard status               # enabled sessions and what the supervisor is doing
llm-switchboard enable c96934f7 [--name "van telemetrics"]
llm-switchboard disable c96934f7
llm-switchboard restart c96934f7
llm-switchboard attach c96934f7      # its tmux window; detach with Ctrl-b d
llm-switchboard new --list
llm-switchboard new ~/dev/obd-things "what it's for"
llm-switchboard new ~/dev/obd-things "logger" --codex "add a logger"
llm-switchboard fork c96934f7 "try another approach" [--folder ~/dev] [--keep]
llm-switchboard search 'can decoder by:me'      # transcript search; same terms as the page
llm-switchboard search 'can decoder' --session codex:019f   # one result's matches in context
llm-switchboard search 'can decoder' --json   # one JSON line per result, for scripts
llm-switchboard index                # catch the transcript index up now
llm-switchboard stop-all             # kill the tmux server and every session in it
llm-switchboard host-authorize m4mac < key.pub   # install a Mac's restricted key (the setup script runs it over SSH)
journalctl --user -u llm-switchboard -f

Where it lives

  • Checkout ~/dev/llm-switchboard; the service runs bin/llm-switchboard serve from it, so a code change needs systemctl --user restart llm-switchboard. Running sessions are untouched: the tmux server is in its own systemd scope and the restarted supervisor adopts the windows.
  • User unit llm-switchboard, started at boot through loginctl enable-linger pi. Port 8777, on localhost and the Tailscale address only; it answers only localhost and Tailscale peers, and binds the Tailscale address once Tailscale is up. serve --host ADDR (repeatable, tailscale for that address) changes where it listens.
  • State: ~/.config/llm-switchboard/sessions.json (enabled sessions) and codex-trash.json (Codex sessions deleted here); trash in ~/.local/share/llm-switchboard/trash/; what the Mac last pushed, and its action queue, in ~/.local/share/llm-switchboard/hosts/m4mac.json; the transcript search index in ~/.local/share/llm-switchboard/transcript-search.sqlite3 and its -wal, -shm and .lock files. To rebuild it from scratch, stop the service, delete all four, and start it again.
  • On the Mac: the launchd job ~/Library/LaunchAgents/dev.llm-switchboard.host-agent.plist, logs (including every upload) in ~/Library/Logs/llm-switchboard/, its record of actions run and the upload quota in ~/.config/llm-switchboard/, its trash in ~/.local/share/llm-switchboard/trash/.
  • Sessions are the same files Claude Code uses, ~/.claude/projects/*/*.jsonl, read in place; Codex sessions come from the daemon socket under ~/.codex/app-server-control/.
  • Tests: python3 -m unittest discover -s tests and tests/browser/run.sh (headless Chromium against a fake home and a fake Codex daemon). The repo's AGENTS.md asks for this guide to be updated with any change in behaviour.
